# 기능별 구현 설명

이 문서는 대시보드의 각 기능이 코드에서 어떻게 동작하는지 설명한다. 실행 방법은 [README](../README.md)에 있다.

## 한눈에 보기

```
브라우저 화면 (public/)
   │  fetch
   ▼
로컬 서버 src/server.mjs  ──  127.0.0.1:4310, 내 컴퓨터에서만 접속
   ├─ 영상 자료     src/youtube.mjs   RSS, yt-dlp
   ├─ 초안 생성     src/generate.mjs  → src/llm.mjs (Claude API 또는 claude CLI)
   ├─ 댓글 검사     src/validate.mjs
   ├─ 운영 규칙     src/rules.mjs
   ├─ 기록 저장     src/store.mjs     SQLite (data/agent.db)
   └─ 게시          src/poster.mjs    Playwright + 내 크롬 프로필
```

외부 라이브러리는 두 개만 쓴다. `yaml`은 설정 파일을 읽고, `playwright`는 크롬을 조작한다. 웹 서버(`node:http`)와 데이터베이스(`node:sqlite`)는 Node 22에 들어 있는 기능을 쓴다. 그래서 설치할 것이 적다.

원칙은 하나다. **규칙은 화면이 아니라 서버가 강제한다.** 화면에서 버튼을 막는 것은 안내용이다. 실제 차단은 게시 직전에 서버가 다시 검사해서 한다.

## 1. 설정 — `config.yaml`, `src/config.mjs`

바꿀 수 있는 값은 모두 `config.yaml` 한 곳에 둔다.

| 항목            | 내용                                                                    |
| --------------- | ----------------------------------------------------------------------- |
| `profiles`      | 크롬 프로필 3개 (유튜브1~3)와 폴더 위치                                 |
| `channels`      | 허용 채널 5곳의 채널 ID와 이름                                          |
| `test_videos`   | 본인 테스트 영상 ID                                                     |
| `posting_scope` | `test_only`(기본): 테스트 영상에만 게시. `channels`: 지정 채널에도 게시 |
| `comment`       | 40~120자, 브랜드 이름 "운명원"                                          |
| `limits`        | 하루 10개, 채널당 영상 5개                                              |
| `rising`        | 뜨기 직전 영상의 기준 (검색어, 조회수 범위, 시간당 조회수)              |

`loadConfig()`는 빠진 값을 기본값으로 채운다. `posting_scope`에 이상한 값이 들어가면 안전한 쪽인 `test_only`로 본다. `loadEnv()`는 `.env` 파일에서 API 키 같은 값을 읽는다. 이미 환경 변수에 있는 값은 덮어쓰지 않는다.

## 2. 영상 불러오기 — `src/youtube.mjs`

**YouTube Data API 키 없이** 동작하게 만들었다.

- **채널 최신 영상** `fetchChannelFeed()`: 유튜브가 공개하는 채널 RSS(`/feeds/videos.xml?channel_id=…`)를 읽는다. 제목, 날짜, 썸네일, 조회수를 정규식으로 꺼낸다. 채널마다 최근 5개를 가져온다.
  - 라이브 다시보기(제목이 `Live streaming of`로 시작)는 뺀다. 자막이 없어서 영상 속 장면을 짚기 어렵기 때문이다.
- **5개 채널 동시 요청** (`server.mjs`의 `POST /api/videos`): `Promise.allSettled`를 써서 한 채널이 실패해도 나머지는 보여 준다. 실패한 채널은 화면에 이름을 알려 준다.
- **영상 자료** `getVideoContext()`: `yt-dlp -J --skip-download`로 제목, 설명, 채널 ID, 조회수를 받는다.
  - 자막: 사람이 단 한국어 자막을 먼저 찾고, 없으면 자동 자막을 쓴다. `json3` 형식을 받아 글자만 이어 붙인다. 자막이 아예 없으면 제목과 설명만 쓴다.
  - 인기 댓글: `comment_sort=top`으로 40개를 받아 답글을 빼고, 좋아요 순으로 20개를 남긴다.
  - 같은 영상을 다시 열 때 기다리지 않도록 서버가 메모리에 보관한다 (`contexts` Map).
- **링크 직접 입력** `parseVideoId()`: `youtu.be/…`, `watch?v=…`, `shorts/…`, `live/…`, 11자리 ID를 모두 받는다. 그다음 서버가 yt-dlp로 **실제 채널 ID를 확인**하고 허용 채널인지 본다. 허용 밖이면 차단하고 기록에 남긴다.

## 3. 뜨기 직전 영상 찾기 — `findRising()`

1. 유튜브 검색 결과 페이지를 "오늘 업로드" 필터(`sp=EgIIAg==`)로 연다. 검색어는 "연애"다. 처음에는 yt-dlp의 `ytsearchdate`를 쓰려 했지만, 지금 버전(2026.08.19)에서 지원하지 않아 바꿨다.
2. 30개 중 조회수 1,000~5,000인 영상만 남긴다.
3. 남은 영상의 정확한 업로드 시각을 4개씩 동시에 조회한다 (`mapLimit`).
4. 시간당 조회수 = 조회수 ÷ 올린 뒤 지난 시간. 150 이상만 보여 준다. 방금 올린 영상의 숫자가 과하게 커지지 않도록 지난 시간은 최소 15분으로 계산한다.

이 영상들은 지정 채널이 아닐 수 있다. 그래서 **초안까지만** 만든다. 서버는 이 영상 ID를 `risingIds`에 기억했다가, 게시 요청이 오면 막고 기록에 남긴다.

## 4. 댓글 초안 생성 — `src/generate.mjs`, `src/llm.mjs`

### AI 연결 (`llm.mjs`)

- `.env`에 `ANTHROPIC_API_KEY`가 있으면 Claude API를 부른다.
- 키가 없으면 내 컴퓨터의 `claude` CLI를 부른다 (`claude -p`). CLI는 임시 폴더에서 실행한다. 프로젝트 폴더에서 실행하면 그 폴더의 지침 파일을 읽어서 답이 흔들리기 때문이다.
- 180초가 지나면 끊고 오류를 알려 준다.

### 프롬프트 (`buildPrompt`)

AI에게 "방금 영상을 끝까지 본 한국인 시청자"라는 역할을 주고, 두 단계로 답하게 한다.

1. `concern`: 영상이 다루는 연애 고민 한 줄 (40자 이내)
2. `comment`: 시청자로서 남길 댓글

그리고 `detail`도 함께 받는다. 댓글에서 짚은 영상 속 말을 자막에 있는 그대로 3~15자 적게 한다. 이 값은 나중에 검사기가 "정말 영상에 있는 말인지" 대조하는 데 쓴다.

AI에게 주는 자료는 제목, 채널, 설명, 자막 앞 7,000자, 인기 댓글 20개, 이미 쓴 댓글 10개다. 답은 JSON 하나로만 받는다. `parseJson()`은 앞뒤에 다른 말이 붙어도 `{ … }` 부분만 꺼낸다.

### 검사 후 다시 쓰기 (`draftComment`)

```
AI 초안 → 검사기 → 통과? ── 예 → 화면으로
                     └ 아니오 → 떨어진 이유를 프롬프트 끝에 붙여 다시 요청 (최대 3번)
```

예를 들어 "글자 수 132자 (기준 40~120자)"라는 이유를 붙이면, 다음 시도에서 AI가 길이를 줄인다. 3번 모두 떨어지면 마지막 초안과 실패 이유를 그대로 보여 준다. 사람이 고칠 수 있게 하기 위해서다.

## 5. 댓글 검사기 — `src/validate.mjs`

AI가 쓴 초안과 사람이 고친 글이 **같은 검사기**를 지난다. 결과는 규칙마다 `{key, label, ok, note}`로 돌려준다. 화면은 이 값으로 ✓/✕ 표를 그린다.

| 규칙                    | 검사 방법                                                                                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 40~120자                | 이모지와 한글이 한 글자로 세어지도록 `[...text]`로 센다                                                                                                        |
| "운명원" 한 번          | 브랜드 이름으로 문장을 잘라 나온 횟수를 센다. 0번이나 2번 이상이면 실패                                                                                        |
| 링크·해시태그 없음      | `http`, `www.`, `.com`/`.kr` 같은 도메인 끝, `#글자`를 정규식으로 찾는다                                                                                       |
| 이용 후기처럼 쓰지 않음 | "봤는데", "맞더라", "다녀왔", "후기" 같은 말을 찾는다. **"운명원"이 들어간 문장에서만** 찾는다. 영상 이야기를 하며 "영상 봤는데"라고 쓰는 것은 괜찮기 때문이다 |
| 영상 속 장면·말 포함    | 아래 설명                                                                                                                                                      |
| 이전 댓글과 다름        | 아래 설명                                                                                                                                                      |

**영상 속 장면·말 확인.** 공백과 문장부호를 지우고 소문자로 바꾼 뒤 비교한다 (`norm`). 둘 중 하나면 통과다.

- AI가 밝힌 `detail`이 자막·제목·설명에도 있고 댓글에도 있다.
- 또는 댓글과 영상 자료가 6글자 이상 연속으로 겹친다 (`longestCommon`). 브랜드 이름은 빼고 비교한다. 사람이 고친 글은 `detail`과 달라질 수 있어서 이 방법을 하나 더 두었다.

찾은 부분은 `locate()`로 원래 댓글에서 다시 찾아 `anchor`로 돌려준다. 화면 미리보기는 이 부분을 색으로 강조한다.

**이전 댓글과 비교.** 두 글을 두 글자씩 잘라 겹치는 비율을 잰다 (bigram Jaccard). 0.5 이상이면 너무 비슷하다고 본다. 비교 대상은 **다른 영상**에 단 댓글과 초안이다. 같은 영상의 초안을 조금 고친 글은 당연히 비슷하므로 뺀다.

## 6. 운영 규칙 — `src/rules.mjs`

| 함수             | 하는 일                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkLoadScope` | 초안까지 허용되는 영상인가: 허용 채널 영상 또는 본인 테스트 영상                                                                                              |
| `checkPostScope` | 게시가 허용되는 영상인가: `test_only`면 테스트 영상만                                                                                                         |
| `checkPost`      | 게시 직전 최종 검사: 설정에 있는 프로필인가 → 게시 범위 → 이 영상에 이미 성공한 댓글이 있는가 (계정과 상관없이 영상당 1개) → 오늘 성공한 댓글이 10개 미만인가 |
| `pickProfile`    | 자동 배정: 가장 오래 안 쓴 계정을 고른다                                                                                                                      |
| `kstDate`        | "오늘"을 한국 시간 기준 날짜로 계산한다                                                                                                                       |

채널 확인에는 화면이 보낸 값을 쓰지 않는다. 서버가 yt-dlp로 받은 채널 ID로만 판단한다. 화면 요청을 조작해도 허용 밖 채널에 게시할 수 없다.

## 7. 기록 — `src/store.mjs`

SQLite 파일(`data/agent.db`)의 `logs` 표 하나에 모든 시도를 남긴다.

- 칸: 시각, 날짜(한국 시간), 영상, 채널, 계정, 댓글, 결과, 이유, 캡처 파일, 댓글 링크
- 결과는 세 가지다.
  - `success`: 게시하고 내 댓글까지 확인함
  - `failed`: 게시를 시도했지만 실패함 (로그인 안 됨, 댓글창 없음 등)
  - `blocked`: 규칙에 걸려 시도하지 않음 (허용 밖 링크, 검사 실패, 영상당 1개, 하루 상한)
- 규칙 검사도 이 표를 쓴다. "이 영상에 성공 기록이 있나", "오늘 성공이 몇 개인가"를 바로 조회한다. 서버를 껐다 켜도 규칙이 유지된다.

## 8. 게시 — `src/poster.mjs`, `scripts/login.mjs`

### 로그인 (`npm run login -- 유튜브1`)

프로필 폴더를 지정해 **일반 크롬**을 연다. 사람이 직접 구글에 로그인하고 창을 닫으면 로그인 상태가 그 폴더에 남는다. 자동 조작 창에서는 구글이 로그인을 막는 경우가 있어서 이렇게 나눴다.

### 게시 순서 (`postComment`)

1. Playwright `launchPersistentContext`로 그 프로필 폴더를 쓰는 크롬을 **화면에 띄운다**. 시연 영상에서 실제 입력이 보이게 하기 위해서다.
2. 영상을 한국어 화면(`hl=ko`)으로 연다. 로그인 버튼이 보이면 "로그인 안 됨"으로 멈춘다.
3. 댓글창이 나올 때까지 아래로 조금씩 스크롤한다 (최대 15번). "댓글 사용 중지" 안내가 보이면 멈춘다.
4. 입력창을 누르고 **한 글자씩** 입력한다. 글자 사이에 60~170ms를 무작위로 쉰다.
5. 게시 버튼을 누른다.
6. 댓글 목록에서 **내 댓글 앞 18자가 들어간 댓글**이 20초 안에 보이는지 확인한다. 보이면 그 댓글의 링크를 가져오고 화면을 캡처한다.

어느 단계에서 실패하든 그 순간 화면을 `data/shots/`에 캡처하고 기록에 붙인다. 시연 영상에서 결과를 볼 수 있도록 성공 후 2.5초 기다렸다가 창을 닫는다.

### 진행 상태 전달

게시는 30초 넘게 걸릴 수 있다. 그래서 서버는 게시를 기다리지 않고 작업 번호(`jobId`)를 바로 돌려준다. 게시 코드는 단계가 바뀔 때마다 상태 글자를 바꾸고("댓글창 찾는 중", "입력 중" …), 화면은 0.6초마다 `GET /api/job`으로 상태를 물어 진행 목록을 갱신한다.

한 번에 하나만 게시한다 (`busy` 플래그). 게시 중에 다시 누르면 거절한다.

## 9. 서버 — `src/server.mjs`

`node:http`로 만든 작은 서버다. 주소 표(`routes`)에 "메서드 + 경로"와 처리 함수를 짝지어 두었다.

| API                   | 하는 일                                                 |
| --------------------- | ------------------------------------------------------- |
| `GET /api/config`     | 계정 준비 상태, 게시 범위, 오늘 사용량, AI 종류         |
| `POST /api/videos`    | 5개 채널 최신 영상                                      |
| `POST /api/resolve`   | 링크 → 영상 ID → 채널 확인. 허용 밖이면 403과 차단 기록 |
| `POST /api/draft`     | 고민 한 줄, 초안, 검사 결과, 게시 전 확인 결과          |
| `POST /api/validate`  | 사람이 고친 글을 다시 검사                              |
| `POST /api/post`      | 최종 검사 후 게시 시작                                  |
| `GET /api/job`        | 게시 진행 상태                                          |
| `GET /api/post-state` | 게시 전 확인 (범위, 영상당 1개, 오늘 남은 개수)         |
| `GET /api/logs`       | 기록 최근 200개                                         |
| `POST /api/rising`    | 뜨기 직전 영상                                          |

**`POST /api/post`가 게시 전에 확인하는 순서**

1. 뜨기 직전 영상인가 → 차단
2. 댓글 검사기를 **다시** 돌림 → 실패하면 차단
3. `checkPost` (계정, 게시 범위, 영상당 1개, 하루 상한) → 실패하면 차단

차단될 때마다 이유와 함께 기록에 남긴다.

안전장치도 몇 가지 넣었다.

- 서버는 `127.0.0.1`에서만 열린다. 같은 와이파이의 다른 기기는 접속할 수 없다.
- 정적 파일과 캡처 파일을 줄 때 `safeJoin()`으로 경로를 정리한다. `../`로 다른 폴더의 파일을 읽을 수 없다.

## 10. 화면 — `public/`

빌드 도구 없이 HTML, CSS, 순수 JavaScript로 만들었다. 서버를 켜면 바로 열린다.

- **세 칸 구조**: ① 영상 불러오기 → ② 영상 선택 → ③ 댓글 달기. 각 칸 제목 옆에 "완료 / 지금 / 대기"를 표시한다 (`renderSteps`). 맨 위 단계 표시도 같은 값을 쓴다.
- **초안 편집**: 글을 고치면 0.3초 뒤에 `/api/validate`로 다시 검사한다. 글자 수 막대는 40~120자 구간과 현재 위치를 보여 준다.
- **규칙 검사표**: 검사기의 `checks`로 ✓/✕를 그리고, 떨어진 규칙은 아래에 이유를 글로 적는다. 색을 구분하기 어려운 사람도 알 수 있게 하기 위해서다.
- **미리보기**: 유튜브 댓글 모양으로 보여 준다. 검사기가 돌려준 `anchor`(영상에서 가져온 말)는 배경색으로, "운명원"은 글자색으로 강조한다.
- **게시 전 확인**: 댓글 검사 통과 여부와 `/api/post-state`의 세 항목을 보여 준다. 하나라도 ✕면 "댓글 달기" 버튼이 꺼진다.
- **기록 표**: 전체 / 성공 / 실패 / 차단으로 거를 수 있다. 차단과 실패는 이유를 함께 보여 준다.
- **디자인**: macOS 최신 디자인을 따랐다. 위쪽 막대와 왼쪽 목록은 반투명이고, 색은 시스템 파랑 하나와 성공·실패 색만 쓴다. 컴퓨터가 다크 모드면 자동으로 어두워진다 (`prefers-color-scheme`).

## 11. 테스트 — `test/`

`npm test`로 17개를 돌린다. 외부 서비스 없이 돌아가도록 AI는 가짜 함수로 바꿔 끼운다.

- `validate.test.mjs`: 글자 수, 브랜드 0번·2번, 링크·해시태그, 후기 표현, 영상 속 말 확인, 유사도, JSON 꺼내기, 실패 이유를 붙여 다시 쓰는지
- `rules.test.mjs`: 허용 채널, 테스트 모드, 설정에 없는 계정 차단, 영상당 1개, 하루 상한, 계정 자동 배정, 한국 시간 날짜, 링크에서 영상 ID 꺼내기. 기록은 임시 폴더의 SQLite로 확인한다.

## 아직 확인하지 못한 것

- **실제 게시**: 로그인한 테스트 계정과 테스트 영상이 아직 없다. 유튜브 화면 구조가 바뀌었다면 `poster.mjs`의 선택자를 고쳐야 할 수 있다.
- **뜨기 직전 영상**: 유튜브 검색 결과 형식에 기대고 있어서, 유튜브가 바꾸면 동작이 멈출 수 있다.
